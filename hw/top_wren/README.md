# Top Wren

Wren is a deliberately minimal, hand-written top-level design whose sole purpose
is to **run code on the ACC** (the Asymmetric Cryptographic Coprocessor,
`hw/ip/acc`). It keeps an Ibex core only to load firmware, drive the ACC, and
report results, and it strips or stubs everything else.

Unlike the reference tops (`top_egret`, `top_dragonfly`), Wren is **not**
generated by `topgen`. It is a small, parameterized SystemVerilog wrapper. This
keeps it easy to read and modify, at the cost of the topgen-based build
integration (see [Build integration](#build-integration)).

Guiding principle for every block: *is it required to run code on the ACC?* If
not, it is omitted (and any interface the ACC needs is driven by a fixed-function
stub). If yes, it uses the simplest implementation that works.

## Block diagram

```
                    +----------------------------------------------------+
   JTAG  <--------->|  rv_dm  (debug + system-bus-access host)            |
                    +--------+-------------------------------------------++
                             | sba (host)                                 |
   Ibex corei (host) --+     |                                            |
   Ibex cored  (host) --+----+----> tlul_socket_m1 (3 hosts) --> merged bus
                                                                    |
                                              tlul_socket_1n (address decode)
                                                                    |
     +----------+----------------+-------------+-----------+--------+--------+
     |          |                |             |           |                 |
   SRAM     rv_dm.mem        rv_dm.regs       ACC        UART          Ibex cfg
 (plain,   (debug ROM)                    (regs+IMEM   (console)
 code+data)                               +DMEM)
                                             |
              ACC inter-module partners (all STUBBED in v1):
                edn_rnd / edn_urnd  <- responding EDN stub (fixed data)
                acc_otp_key         <- fixed reset-default scramble key
                keymgr_key          <- invalid (valid=0)
                kmac                 <- APP_RSP_DEFAULT (AccPQCEn=0, unused)
                lc_escalate / rma    <- Off
                alerts               <- local rx tie-off; alert_tx to top ports
```

## Contents of a Wren "run code on ACC" flow

1. Firmware (compiled for Ibex) is placed in the SRAM.
   * In simulation it is backdoor-loaded via a VMEM (`SramInitFile`).
   * On FPGA it is loaded over JTAG (`rv_dm` system-bus access).
2. Ibex boots from the SRAM base, configures the UART, waits for the ACC to
   finish its power-on secure wipe, writes an ACC program into IMEM, issues
   `CMD=Execute`, polls `STATUS`, reads `ERR_BITS`, and prints the result.

## Modules

| Block            | Status | Notes |
|------------------|--------|-------|
| `rv_core_ibex`   | real   | `ICache=0`/`ICacheScramble=0` (drops its EDN + icache-OTP-key dependencies); reused from `lowrisc:egret_ip:rv_core_ibex`. |
| `acc`            | real   | `AccPQCEn=0` (base bignum ISA; PQC needs real KMAC — see follow-ups). |
| code+data SRAM   | real   | Plain `tlul_adapter_sram` + `prim_ram_1p_adv`, unscrambled, ifetch always enabled. See [Memory deviation](#memory-deviation). |
| `rv_dm` + JTAG   | real   | Debug + firmware load; `sba` is a TL-UL host. |
| `uart`           | real   | Console output. |
| TL-UL fabric     | real   | `tlul_socket_m1` (3 hosts) → `tlul_socket_1n` (6 devices) with a hand-written address decode. |
| clk/rst          | real   | Single external clock and reset; no clkmgr/rstmgr/pwrmgr. |
| entropy (edn/csrng/entropy_src) | **stub** | Responding EDN stub feeds the ACC (`wren_edn_stub`). Mandatory — the ACC secure wipe blocks on a URND ack. |
| `otp_ctrl`       | **stub** | `wren_acc_otp_key_stub` returns the fixed reset-default scramble key. |
| `keymgr`         | **stub** | `keymgr_key` tied to invalid. |
| `kmac`           | **stub** | `kmac_data_i = APP_RSP_DEFAULT`; unused while `AccPQCEn=0`. |
| `lc_ctrl`        | **stub** | escalate/rma tied `Off`. |
| `alert_handler`  | **stub** | Per-block `alert_rx` tied to `ALERT_RX_DEFAULT`; ACC `alert_tx` exposed as top ports. |

The stubbed blocks are selectable via the `EdnEn`/`KmacEn`/`KeymgrEn`/`OtpEn`
(and `AccPQCEn`) parameters on `top_wren`. v1 implements the stub path only and
asserts these are 0; the real blocks are follow-up work.

## Address map

Flat 32-bit map on the single main crossbar (see
[`rtl/top_wren_pkg.sv`](./rtl/top_wren_pkg.sv)):

| Device        | Base          | Size   | Notes |
|---------------|---------------|--------|-------|
| SRAM          | `0x1000_0000` | 128 KiB | code + data; Ibex `boot_addr` = this |
| rv_dm mem     | `0x0001_0000` | 4 KiB  | debug ROM; Ibex `Dm*` params match |
| rv_dm regs    | `0x4120_0000` | 4 KiB  | |
| ACC           | `0x4130_0000` | 128 KiB | regs `+0x0`, IMEM `+0x8000`, DMEM `+0x18000` |
| UART          | `0x4000_0000` | 4 KiB  | |
| Ibex cfg      | `0x411F_0000` | 4 KiB  | `cfg_tl_d` |

Out-of-range accesses hit the `tlul_socket_1n` built-in error responder.

## Boot flow

Ibex is released from reset immediately (`lc_cpu_en` and `pwrmgr_cpu_en` tied
`On`; there is no pwrmgr). It fetches its first instruction at `boot_addr + 0x80`
(the reset vector) and vectors exceptions to `boot_addr`. The linker script
[`sw/wren_sram.ld`](./sw/wren_sram.ld) places a trap handler at SRAM offset `0x0`
and the reset entry at `0x80`.

Instruction fetch from the plain SRAM is enabled unconditionally
(`en_ifetch_i = MuBi4True` on the adapter), so no CSR setup is needed before the
first fetch.

## Build integration

Wren is built via **FuseSoC** cores (not the Bazel `pavona_top` machinery, which
expects topgen-generated artifacts):

* `top_pkg.core`, `top_racl_pkg.core` — minimal top support packages. They
  declare the `lowrisc:virtual_constants:*` virtuals that the shared IPs depend
  on, so Wren's versions are selected instead of another top's.
* `top_wren.core` — the top RTL, with a `lint` target.
* `chip_wren_verilator.core` — the Verilator simulation model, with `sim` and
  `lint` targets.

### Lint

```sh
fusesoc --cores-root=. run --target=lint lowrisc:systems:top_wren
```

### Build the Verilator model

```sh
fusesoc --cores-root=. run --target=sim --setup --build \
  lowrisc:systems:chip_wren_verilator
```

The `lowrisc:prim_generic:all` dependency forces the generic prim
implementation (otherwise the prim abstraction pulls in Xilinx/ASAP7 technology
cells that Verilator cannot elaborate).

## Running the ACC smoke test

The firmware in [`sw/`](./sw) loads a one-instruction (`ECALL`) program into the
ACC, runs it, and prints `wren: ACC PASS` if `ERR_BITS == 0`. Building it needs a
bare-metal RISC-V toolchain and `srec_cat`:

```sh
make -C hw/top_wren/sw
fusesoc --cores-root=. run --target=sim \
  --SramInitFile=$(pwd)/hw/top_wren/sw/wren_acc_smoke.vmem \
  lowrisc:systems:chip_wren_verilator
# expect: "wren: ACC PASS" on stdout
```

The simulation wrapper ([`rtl/chip_wren_verilator.sv`](./rtl/chip_wren_verilator.sv))
includes a UART-RX monitor that decodes the console and streams it to stdout. Its
`UartCyclesPerBit` must match the UART NCO configured by the firmware
(`sw/wren_acc_smoke.c`); tune the pair together.

## FPGA (CW310)

[`rtl/chip_wren_cw310.sv`](./rtl/chip_wren_cw310.sv) is a structural bring-up
skeleton: it maps `top_wren` I/O onto FPGA pins and synchronizes the reset. It
still needs an MMCM/clkgen for the core clock, CW310 XDC pin/clock constraints,
and a Vivado bitstream target before it can run on hardware.

## Notable design points

### Memory deviation

The code/data memory is a plain, unscrambled SRAM
(`tlul_adapter_sram` + `prim_ram_1p_adv`) rather than a full `sram_ctrl`. Reasons:

* `sram_ctrl` gates instruction fetch on an `EXEC` CSR, which creates a
  chicken-and-egg problem when booting directly from SRAM (nothing has run yet to
  set the CSR).
* `sram_ctrl` scrambles its RAM, which makes backdoor-loading firmware in
  simulation awkward.

The plain SRAM avoids both, and the adapter still generates TL response integrity
for Ibex. A real `sram_ctrl` can be added behind a parameter later.

### The EDN stub is mandatory

The ACC's power-on secure wipe blocks waiting for a URND reseed acknowledge
(`hw/ip/acc/rtl/acc_start_stop_control.sv`, `acc_rnd.sv`). A non-responding or
tied-off EDN would hang the ACC forever, so `wren_edn_stub` completes the EDN
handshake with fixed (per-request varying) data. The `SecSkipUrndReseedAtStart`
ACC parameter does **not** bypass this initial reseed.

### Alerts

There is no alert handler. Each block's `alert_rx_i` is tied to
`prim_alert_pkg::ALERT_RX_DEFAULT` (never all-zero — that would violate the
differential encoding), and the ACC's `alert_tx` outputs are exposed as
top-level ports for observation.

## Follow-ups

The `*En` parameters are the intended extension points:

* Real KMAC + `AccPQCEn=1` → unlocks ACC post-quantum (ML-KEM / ML-DSA)
  acceleration. This is the gate for PQC; a zero KMAC stub cannot satisfy the
  KMAC application handshake.
* Real `entropy_src` + `csrng` + `edn` chain (the heaviest interconnect).
* Real `keymgr`, `otp_ctrl`, `lc_ctrl`, `alert_handler`.
* A real `sram_ctrl` behind a parameter.
* CW310 clocking + constraints, and (if desired) topgen/Bazel integration.
